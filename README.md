# TASM-DOS-builder
Набор инструментов для разработки и автоматической сборки программ под MS-DOS с использованием Turbo Assembler (TASM) и Turbo C (TC).

Сборка организована через GNU Make, а запуск программ выполняется внутри QEMU на DOS-образе.

## Требования

Для работы проекта необходимы:

QEMU — запуск MS-DOS;
Python 3 — подготовка FAT12-образа и перенос файлов;
GNU Make — автоматизация сборки;
DOS-образ с установленными:
TASM;
Turbo C / TC.
### Linux

Установить необходимые инструменты можно через пакетный менеджер своего дистрибутива.

Например, для Arch Linux / CachyOS:
```
sudo pacman -S qemu-desktop python make
```
Проверить установку:
```
qemu-system-i386 --version
python3 --version
make --version
```
### Windows

Для установки используется Chocolatey.

После установки Chocolatey:
```
choco install qemu python make
```
Проверить:

qemu-system-i386 --version
python --version
make --version

Название команды Python может отличаться в зависимости от установки. При необходимости Makefile можно запускать с PYTHON=python.

### DOS-образ

Для работы необходим DOS-образ, содержащий установленный TASM и Turbo C.

В DOS должны быть доступны необходимые инструменты сборки, например:
```
C:\TASM
C:\TC
```
Turbo C должен иметь свои библиотеки, заголовочные файлы и startup-файлы (C0*.OBJ и т. д.).

Сам проект не устанавливает DOS, TASM или Turbo C автоматически — Makefile использует уже подготовленный DOS-образ.

Структура проекта

Пример:
```
project/
├── Makefile
├── make_fat.py
├── AUTOEXEC.BAT
├── BUILD.BAT
├── BUILDCOM.BAT
├── RUN.BAT
├── GUI.BAT
│
├── TASM-files/
│   └── ...
│
└── testCode/
    └── main.c
```
testCode является примером проекта для проверки работы сборочной системы.

При использовании собственного проекта его можно заменить на свою папку.

Настройка Makefile

В Makefile необходимо указать папку с исходным проектом.

Например:
```
PROJECT_DIR := testCode
```
Если проект находится в папке:
```
myProject/
```
нужно заменить на:
```
PROJECT_DIR := myProject
```
Таким образом Makefile не привязан непосредственно к testCode.

Для проверки работоспособности сборщика можно оставить:
```
PROJECT_DIR := testCode
```
и использовать предоставленный тестовый проект.

Makefile

Основная задача Makefile — автоматизировать весь процесс:
```
исходный код
     ↓
подготовка файлов
     ↓
создание нового FAT12-образа
     ↓
перенос файлов на A:
     ↓
запуск QEMU
     ↓
сборка в DOS
     ↓
запуск программы
```
При подготовке файлов Python-скрипт также приводит текстовые файлы к формату, пригодному для работы старых DOS-программ.

В частности, исходный C-код, созданный в Linux/Windows современным редактором, преобразуется в DOS-совместимый текстовый формат перед помещением на виртуальную дискету.

Основные команды
```
make build
```
Выполняет сборку проекта.

Для C-программы:
```
make build
```
происходит примерно следующее:
```
main.c
  ↓
подготовка DOS-совместимого файла
  ↓
exchange.img
  ↓
QEMU
  ↓
BUILD.BAT
  ↓
Turbo C
  ↓
MAIN.EXE
```
Для ASM-проекта аналогично используется TASM.
```
make build
```
Собирает программу в формате .COM, если соответствующий сценарий сборки предусмотрен проектом.

Например:
```
make build-com
```
Используется отдельный DOS-сценарий:
BUILDCOM.BAT

Собирает и запускает программу.
```
make run

Сценарий:

Makefile
   ↓
RUN.BAT
   ↓
сборка
   ↓
запуск MAIN.EXE / MAIN.COM
```
После выполнения программы QEMU может завершаться автоматически в зависимости от настроек RUN.BAT и DOS-окружения.

Запускает DOS в GUI-режиме без выполнения основной программы.
```
make gui
```
Используется:
GUI.BAT

Он предназначен для ручной работы внутри DOS.
Например:
```
A:\>
C:\>
C:\TC>
```
Можно самостоятельно выполнять команды, запускать Turbo C/TASM и отлаживать программу.

Проверка сборщика

Для проверки можно использовать готовый проект:
```
testCode/
```
В Makefile:

PROJECT_DIR := testCode

После этого:
```
make build
```
Если всё настроено правильно, Makefile:

создаст новый образ обменной дискеты;
преобразует исходные файлы в DOS-совместимый формат;
перенесёт их на виртуальную дискету;
запустит QEMU;
DOS выполнит соответствующий .BAT;
Turbo C или TASM соберёт программу.
Почему используется exchange.img

exchange.img является промежуточным FAT12-образом, через который файлы передаются между основной ОС и DOS.

Схема:
```
Linux / Windows
      │
      │ Makefile
      ▼
 make_fat.py
      │
      ▼
exchange.img
      │
      │ QEMU
      ▼
     A:
      │
      ▼
   MS-DOS
```
Образ создаётся заново при соответствующей сборке, поэтому старые .BAT, .C, .ASM и другие файлы не должны оставаться от предыдущего запуска.

Редактирование исходников

Исходный код можно редактировать обычными современными редакторами:

Neovim;
VS Code.

DOS-редактор для подготовки исходников не требуется.

Например:

main.c
main.asm

редактируются в Linux/Windows, после чего Makefile автоматически подготавливает их для DOS.
```
Общая схема работы
             VS Code / Neovim
                    │
                    ▼
             Исходный проект
                    │
                    ▼
                 Makefile
                    │
                    ├── make build
                    ├── make build-com
                    ├── make run
                    └── make gui
                    │
                    ▼
              make_fat.py
                    │
          DOS-преобразование файлов
                    │
                    ▼
              exchange.img
                    │
                    ▼
                  QEMU
                    │
                    ▼
                 MS-DOS
                    │
             ┌──────┴──────┐
             ▼             ▼
           TASM        Turbo C
             │             │
             └──────┬──────┘
                    ▼
              готовая программа
```
Главная идея проекта — не работать с DOS-файлами вручную: исходник редактируется в Linux/Windows, а Makefile автоматически подготавливает его, передаёт в DOS и запускает нужный сценарий сборки.
